# AI Usage Log

This document records the interaction, delegation, and verification process between the human engineer and the AI Copilot (Antigravity) during the development of DomainCopilot. 

As per requirements, this log focuses heavily on honesty regarding AI mistakes, corrections, and the division of labor.

## Phase 1: Foundational Scaffolding (Steps 1 - 12)

### What I Delegated
- **Project Structure**: Scaffolded the .NET 10 solution, Onion architecture layers (Core, Service, Repository, APIs), and test projects.
- **Boilerplate Code**: Generated domain entities (`CitizenCase`, etc.), `BaseSpecification<T>`, and `ExceptionMiddleware`.
- **Infrastructure Setup**: Wrote `docker-compose.yml`, multi-stage Dockerfiles, and the `.env` templates.
- **Frontend Skeleton**: Scaffolded the Angular 17 app with `ng new`, generated 6 routed components, an `authGuard`, and a `correlationIdInterceptor`.
- **CI/CD**: Wrote the `.github/workflows/ci.yml` pipeline for building, testing, linting, and secret scanning (TruffleHog).
- **Documentation**: Generated initial drafts for `BRD.md`, `ADR-0001`, and `SECURITY.md`.

### What I Wrote Myself
- **The Blueprint**: I provided the strict architectural rules (Talabat-style Onion, no Core dependencies, explicit layers) and the step-by-step ordered execution plan via a master prompt.
- **Agent Rules**: I consolidated and authored the rules inside `AGENTS.md` to programmatically constrain the AI's behavior and define the T3/D4 workflows.
- **Workflow Enforcement**: I established the specific frontend Angular rules (3 files per component, strict folder hierarchy) and appended them to the agent instructions.

### Where the AI Misled Me (Mistakes & Corrections)
1. **Branching Violations**: During the initial execution (Steps 6-8), the AI became overly eager and committed code *directly* to the `main` branch, violating the strict "All work merges via Pull Request" rule.
   - *Correction*: I caught this immediately. The AI had to rewind the git history back to Step 5 (`git reset --hard`), manually recreate the feature branches pointing to the correct commits, and push them.
2. **Stacked Branch Auto-merging**: Because the AI re-created the feature branches sequentially on top of each other (stacked branches), merging the final Angular PR effectively fast-forwarded and merged all previous scaffolding steps simultaneously. 
   - *Correction*: This caused GitHub to register the intermediate branches as having "0 new commits." While the code merged correctly, it required understanding Git's DAG to explain why the other PRs couldn't be opened.
3. **Angular CLI Execution Errors**: The AI attempted to run `ng generate` commands using `npx` inside the frontend directory, which silently failed (returning "Nothing to be done") because it misinterpreted how the CLI handles existing files and command arguments in the sandbox.
   - *Correction*: The AI had to inspect the directory, realize the components were already generated by my manual `ng new` run, and pivot to just writing the routes and interceptors.

### How I Verified
- **Automated Tests**: Ensured the AI ran `dotnet test` on the generated xUnit projects (confirming `CitizenCase` constructor validation).
- **Build Checks**: Verified compilation of the Angular app via `npm run build`.
- **Git History Auditing**: Manually inspected `git log` and the GitHub UI to verify the branch rewind and ensure no secrets were committed.
