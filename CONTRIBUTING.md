# Contributing

We'd love for you to contribute to our source code and to make this project even better!

## Branch Naming
Please use the following conventions when creating a new branch:
- `feat/`: For new features (e.g., `feat/add-login-component`)
- `fix/`: For bug fixes (e.g., `fix/header-styling`)
- `docs/`: For documentation updates (e.g., `docs/update-readme`)

## Conventional Commits
We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification for our commit messages. 
Examples:
- `feat: add user authentication flow`
- `fix: resolve null reference in user service`
- `docs: update setup instructions in README`

## Pull Request Workflow
1. Create a branch from `main` using the naming convention above.
2. Make your changes and commit them using Conventional Commits.
3. Push your branch and open a Pull Request (PR) against `main`.
4. Fill out the **Pull Request Template** completely.
5. **Self-Review:** Before requesting a review, review your own code. Check for leftover debug statements, verify styling, and ensure tests pass.
6. A review from a code owner is required before the PR can be merged.
